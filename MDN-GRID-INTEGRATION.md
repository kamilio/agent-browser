### Contracts to settle before parallel coding

- **Computed model:** separate container tracks/areas/auto-placement settings from item line/area placement. Preserve named lines, quoted area cells, intrinsic keywords, `minmax()` bounds and `fr` factors; retain percentages until a valid basis exists. Cover observed `grid-template-columns`, `grid-template-rows`, `grid-template-areas`, `grid-area`, and the implicit tracks/placement their omissions require. Define unsupported syntax explicitly rather than accepting everything.
- **Shared alignment:** [css-flex.ts](src/css-flex.ts#L9) currently owns `order`, `justify-content`, `align-*` and gaps. Reuse one authoritative declaration/cascade representation; define grid-specific used behavior and any missing `justify-items`/`justify-self` support. The captured sidebar “gaps” are explicit tracks, not declarations of `column-gap`.
- **Layout boundary:** one formatting tree and stable ids/refs; allocated item rectangles plus width/height definiteness; nested-dispatch context; normal layout output and cumulative work/text metrics. Ownership must handle grid-in-grid, flex-in-grid and grid-in-flex without duplicate traversal, box publication or budget resets.

## Reuse, interactions and limits

- [CSS math](src/css-math.ts#L3) already bounds `calc/min/max/clamp` length-percentage expressions: 4,096 source code units, 16,384 computed units, 256 nodes, depth 32, 32 arguments. [Box computation](src/css-box.ts#L171) supplies viewport/font unit conversion; [computeFlexStyle](src/css-flex.ts#L226) shows reuse for gaps. `minmax()` is a grid track construct, not `min()`/`max()`; `fr` is absent from both [box units](src/css-box.ts#L46) and [math dimensions](src/css-math.ts#L30). Reuse length leaves, not the entire track grammar.
- Preserve [layoutNumber / resolveLayoutLength](src/layout-values.ts#L8) finite/bounded checks (absolute length ceiling 16,777,216). [Formatting limits](src/formatting-tree.ts#L42) cap owned nodes/boxes at 50,000, depth at 256, text at 1,000,000 code units and work at 2,000,000. [Public document layout](src/document-layout.ts#L188) retains its 2,000,000 work ceiling even though [flex helper limits](src/flex-layout.ts#L26) are larger. Bound track counts, implicit-track growth, area cells, spans and placement searches; charge aggregate nested measurement/reflow and preserve text limits. Do not multiply independent helper budgets or raise limits to obtain acceptance.
- Height definiteness is essential: the captured body has `min-height`, not a declared definite `height`. Do not assume viewport height is the row-allocation basis or distribute an invented remainder into `1fr`. Carry the existing `containingHeight`, `contentHeightDefinite` and `intrinsicHeight` distinctions into the grid contract.
- Item sizing must reconcile borders/padding, auto margins, min/max constraints, percentage cycles, replaced elements, stretch and width-dependent text heights. Preserve independent formatting contexts rather than applying ordinary block margin collapse across grid items. Inline-grid also requires an explicit atomic-inline policy; do not imply it works merely because display parses.
- Preserve paint/hit order as well as geometry: [layout-paint-order](src/layout-paint-order.ts#L63) recognizes flex items/atomics, [stacking-order](src/stacking-order.ts#L66) reads order-modified children, and [formatting z-index retention](src/formatting-tree.ts#L358) recognizes flex items. Generalize deliberately for grid items without changing DOM order. Audit [positioned layout](src/out-of-flow-positioning.ts#L240), relative translations and geometry invalidation for grid containing blocks, out-of-flow children and overlap.

**Normative research remains required:** exact grid track sizing (especially indefinite `fr`, automatic minimums and spanning contributions), implicit placement and named-line/area resolution, mismatched area/track dimensions, baseline/stretch behavior, intrinsic percentage cycles, out-of-flow grid positioning and inline-grid baselines. These local modules and captures are not specification evidence. Select and document a bounded supported profile after primary-spec research; no claim of CSS Grid conformance or unverified algorithm is made here.

## Remaining non-grid blockers

1. **Rejecting CSS diagnostics remain global.** The [existing issue predicate](src/formatting-tree.ts#L847) does not ignore unknown paint properties, unsupported selectors or at-rules just because grid geometry exists. The report's [native samples](MDN-NATIVE-FORMATTING.md#L34) include `border-radius`, `vertical-align`, `color-scheme`, `@font-face` and `.5ch`. They do not attribute all diagnostic occurrences or identify winners. Implement/document remaining supported profiles; do not strip stylesheet input or blanket-suppress errors.
2. **Logical box properties and units:** captured `margin-inline`, `padding-inline`, and conditional `inset` are outside the current [physical box property list](src/css-box.ts#L15); `svh` and `ch` are outside its unit grammar. Logical mapping, font/viewport-unit semantics and computed-style integration need separate work. Grid's math reuse does not solve them.
3. **Responsive conditions:** arithmetic media values need actual support and contextual evaluation. Preserving an advisory diagnostic is honest, but is not responsive-layout acceptance. Parent selector acceleration is likewise not implementation of unsupported selector syntax.
4. **Sticky/overflow and newly reachable content:** captured header/sidebars use sticky positioning and sidebar scrolling. Current traversal emits [position/overflow layout issues](src/formatting-tree.ts#L335). Their source presence is known; new node-specific blockers after grid traversal are not yet measured. Other reachable unsupported elements/displays may surface as well. The original deferred body prevents claiming a complete remaining-blocker inventory.
